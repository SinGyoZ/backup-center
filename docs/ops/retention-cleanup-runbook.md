# 保留期清理上线手册（bc:cleanup-retention）

## 0. 一句话

`bc:cleanup-retention` 是**删数据**命令（删数据库记录 + 删云端归档），其 4 条护栏当初是手工推演 8 个场景、从未真实执行过。
**上线前必须在真实数据跑一次 `--dry-run`，确认"将删除 N 条"符合预期，再启用 03:30 调度。**

---

## 1. 前置检查（逐条确认）

```bash
# ① rclone 是否可用（不可用则只清 DB，云端归档变孤儿文件）
command -v rclone

# ② 调度是否已注册（应能看到 bc:cleanup-retention ... dailyAt 03:30）
php artisan schedule:list

# ③ 系统 crontab 是否挂着 schedule:run（没有的话调度根本不触发）
crontab -l | grep schedule:run
```

只有 `backup_tasks.retention_days` **非 null 且 > 0** 的启用任务才会被处理，其余一律跳过（护栏 1）。

---

## 2. 执行 dry-run（只统计，不删除）

```bash
cd /path/to/backend
php artisan bc:cleanup-retention --dry-run
```

命令内 dry-run 分支在删除前 `continue`，**不执行 rclone、不删数据库记录**，可以放心跑。

---

## 3. 怎么读输出

每行格式：

```
[dry-run] 任务「X」(id=N, 保留 D 天, 早于 2026-10-07 03:30:00)：将删除 A 条记录 / B 个云端文件
```

结尾汇总：

```
[dry-run] 汇总：涉及任务 X 个, 跳过(retention_days 无效) Y 个, 删除记录 Z 条, 云端删除成功 0 / 失败 0, 派发 Agent 清理指令 0 条, 对账指令 0 条（其中失败 0 条）
```

（dry-run 下"云端删除成功/失败"恒为 0，属正常，因为它根本没调 rclone。）

---

## 4. 判读红线 —— 出现任一条，先停下，别启用调度

| # | 现象 | 含义 | 动作 |
|---|---|---|---|
| 1 | 汇总里"跳过(retention_days 无效)"数量很大 | 大量任务没设 retention_days，或设成了 0/负数 → 护栏 1 生效 | 确认是不是配置漏了，而不是以为"已经在清理" |
| 2 | 某任务 A 条数**接近该任务备份总数** | 护栏 4 只按"每个来源各保最新 1 条成功"，删完几乎不剩 | 属预期行为；若需更多历史，调大 retention_days |
| 3 | B（云端文件）**远大于** A（记录数） | 一条记录对应多个 Storage 副本 | 确认 rclone 可用，否则会残留大量孤儿云端文件 |
| 4 | 开头出现 `⚠ 后端容器内未检测到 rclone` | 本次只会清 DB，云端归档删不掉 | **必须先装 rclone 再上线**，否则云端无限累积 |
| 5 | A 很大（≥500） | 护栏 2 每站单次上限 500 条 | 属预期，会分多天删完；不是故障 |

---

## 5. 护栏 4 的分组口径（历史缺陷已修复）

早期版本护栏 4 只按站保留"最新 1 条 success"，多备份目录场景会把其中一个目录的最新备份一并删掉。

**现已修复**：`backup_logs` 增加了来源列 `source_key`（`self:dir`=目录打包、`self:snapshot`=目录快照、`ext:<path>`=归档收集），
护栏 4 改为**按 source_key 分组各保留最近 1 条成功**——任务配了 P1、P2 两个目录时，
P1、P2 各自的最近 1 条成功都会被保住（`CleanupExpiredBackups.php` 护栏 4 注释）。

---

## 6. 确认无误后再启用（建议试点先行）

1. **单任务试点**：把其余任务的 `retention_days` 临时置空（护栏 1 会跳过它们），
   只留 1 个备份量小、保留期明确的任务，跑一次**真实清理**（不带 `--dry-run`）。
2. **试点核对**：该任务备份数按预期减少 / 云端文件确实消失 / **每个来源的最近 1 条成功仍在**。
3. **全量启用**：恢复其余任务 `retention_days`，确保 crontab 挂着 `schedule:run`。

---

## 7. 应急

若发现删错了：云端文件已被 rclone 删除，**不可恢复**。
所以 §2 的 dry-run 与 §6 的单站试点不是可选项，是必做项。
