# Backup Center（目录备份版）需求说明

> 本文档描述本 fork 的目标形态。原「网站备份」版需求文档见 `docs/archive/`。
> 改造版：备份对象由「网站」泛化为「服务器任意目录」，全链路去除网站语义。

## 1. 定位

自托管的**多服务器目录备份编排系统**。一台 Center 统一管理多台机器上的目录备份：
管理员在网页上定义「备份任务」（一个任务 = 一组目录 + 备份方式 + 存储目标 + 保留策略），
装在目标机上的 Agent 按指令执行备份并推送到远端存储，Center 集中查看记录、统一执行保留期清理与恢复。

- **Center**：Laravel 12 后端 + Vue 3 前端（Docker Compose 部署）
- **Agent**：Go 编写的轻量代理（systemd 服务），v0.18.0，装在每台被备份机器上
- **存储**：S3 兼容 / SFTP / FTP-FTPS / WebDAV，可同时挂多个；可标记「强制」让所有任务自动多推一份

## 2. 核心概念

### 2.1 备份任务（BackupTask）

| 字段 | 说明 |
|---|---|
| `name` | 任务名，**同时是存储端归组目录名**（`<任务名>/YYYYMMDD/`） |
| `server_id` | 所属服务器（目标机） |
| `backup_paths` | 目录列表 `[{label, path, pattern}]`（最多 20 条）；label 用于打包/快照的产物命名 |
| `retention_days` | 保留天数（1–3650；空/0 = 不参与自动清理） |
| `schedule` + `sync_mode` | 定时方式：auto（Agent 每 2 分钟扫描）/ scheduled（每天 HH:MM 派发） |
| `backup_source` × `backup_mode` | 决定备份方式（见 2.2） |
| `incremental_storage_id` | 目录快照的目标存储（仅 SFTP + SSH 私钥 + 未加密） |
| `restore_mode` | 恢复模式：lite 留档 / advanced 自动 |
| `status` / `remark` | 启用停用、备注 |

### 2.2 三种备份方式

| 方式 | 字段组合 | 行为 |
|---|---|---|
| **归档收集** | external + full | Agent 周期扫描任务目录（glob pattern），发现新归档文件即上报并上传。适合收集面板/脚本产出的现成备份 |
| **目录打包** | self + full | Agent 对 `backup_paths` **逐目录** `tar -czf` 打包（`-C 父目录 目录名` 约定），产物 `<任务>-dir-<label>-<时间戳>.tar.gz`，支持每天定时或手动立即打包 |
| **目录快照** | self + incremental | Agent 对每条目录做 rsync `--link-dest` 硬链快照直推 SFTP 存储（`<base>/<任务>/<label>/<时间戳>/`），仅传输变化部分；无基线时自动全量 |

### 2.3 记录与来源目录（origin_path）

每次备份在 `backup_logs` 落一条记录，新增 `origin_path`（来源目录）：
归档收集=扫描文件的父目录；目录打包=被打包的目录；目录快照=被快照的目录。
**自动恢复的解压目标 = origin_path 的父目录**（tar 顶层条目为目录名本身，解压即原位覆盖）。

### 2.4 恢复

- **留档恢复（lite）**：从存储把备份文件下载到本机指定目录留档，不动线上数据。
- **自动恢复（advanced）**：Agent 先把目标目录现状自动预备份，再解压/同步覆盖到 `origin_path` 记录的来源目录。记录缺失 `origin_path` 时该条被跳过并提示改用留档恢复。

## 3. Center ↔ Agent 协议（v2，目录备份版）

| 项 | 约定 |
|---|---|
| 任务清单 | `GET /api/agent/tasks` → `{storages[], tasks[]}`；task item：`{id, name, backup_paths[{path,pattern,label}], retention_days, sync_mode, storage_ids, backup_source, backup_mode, incremental_storage_id}` |
| 注册配置 | `config: {heartbeat_interval, task_refresh_interval, scan_interval}` |
| 备份上报 | `POST /api/agent/report`：`{task_id, filename, full_path, size, backup_at, status, duration_seconds, batch_code, origin_path}`；幂等键 (task_id, full_path) |
| 指令类型 | `sync_now` / `pack_backup`（目录打包）/ `incremental_backup` / `restore`（含 `origin_path`）/ `cleanup_retention` / `update` |
| 定时派发 | `tasks:dispatch-scheduled-sync`（每分钟）：external 任务派 sync_now（按服务器去重）；self 任务按 backup_mode 派 pack_backup 或 incremental_backup |
| 产物命名 | 打包归档 `<safe任务>-dir-<safeLabel>-<时间戳>.tar.gz`；快照 `<safe任务>-snap-<safeLabel>-<时间戳>` |
| source_key | `self:dir`（目录打包）/ `self:snapshot`（快照）/ `ext:<path>`（归档收集）；保留期清理按 source_key 分组各保最近 1 条成功 |

## 4. 保留期清理

`bc:cleanup-retention`（调度约 03:30）：只处理 `retention_days` 有效且启用的任务；
超期 = `backup_at < now - retention_days`；护栏——不删 running、每任务单次上限 500 条、
**每个 source_key 分组各保留最近 1 条成功**（多目录任务每个目录的最新备份都会保住）。
Agent 在线的服务器派发 `cleanup_retention` 指令（不带凭据），其余由 Center 侧 rclone 兜底。

## 5. 本版移除的原有能力（相对原仓库）

- 域名字段（domain）、网站根目录绑定（bind_token / web_root / `.bc-bind` 密钥文件）
- 数据库导出与导入（db_* 配置、mysqldump/pg_dump、`-db-` 产物与自动导库恢复）
- 数据库备份需求可由「先 dump 到目录、再建归档收集任务收走」的方式覆盖

## 6. 兼容性

- 全新部署（迁移已按最终形态重写），**不支持从原「网站版」数据库直接升级**；旧数据请用原版系统导出。
- Center 与 Agent 必须同为目录备份版（v0.18.0）配套部署，协议不向后兼容；升级 Center 后需重装或远程升级 Agent。
